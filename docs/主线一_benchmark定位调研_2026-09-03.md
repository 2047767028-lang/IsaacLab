## 2. 竞品格局：家具装配 / 双臂 benchmark 这块地已经很挤

按时间倒序，全部核对过原文摘要：

| 工作 | 时间 | 占了什么 |
|---|---|---|
| **FurnitureVLA** [2607.01212](https://arxiv.org/abs/2607.01212) | 2026-07-01 | 自称"**第一个**真实尺度双臂家具装配的系统研究"。含：任务形式化 + **可扩展仿真流水线做专家数据生成与评测** + **单操作员双臂 VR 遥操作系统**。7 个子任务 / 1550 控制步。仿真成功率 48%→80%，真机 Kinova Gen3 只掉 16%。**未发现开源代码/项目页。** |
| **DuoBench** [2606.11901](https://arxiv.org/abs/2606.11901) | 2026-06-10 | 双臂 benchmark，**FR3 Duo 平台**（就是双 Franka），11 个任务 / 4 类协调模式，仿真+真机，**阶段化评测方案，支持超越二元成功率的细粒度语义失败分析**，全任务人类遥操作数据集，跑了若干 IL 和 VLA 基线。 |
| **A3D** [2601.11076](https://arxiv.org/abs/2601.11076) | 2026-01-16 | 双臂家具装配（一臂扶持一臂操作），**自建仿真环境：8 类家具、50 个零件**，专为双臂协作评测设计。 |
| **Manual2Skill++** [2510.16344](https://arxiv.org/abs/2510.16344) | 2025-10（2026-03 修订） | 连接件感知的装配，**Isaac Lab 上的装配 benchmark**：IKEA 椅/鞋架/飞机模型/乐高，含榫卯、木销、螺丝等连接类型，IKEA 椅 6 件 22 步。 |
| **FurnitureBench** [RSS 2023](https://arxiv.org/abs/2305.12821) | 2023 | 老祖宗。真实世界家具装配 benchmark + FurnitureSim（Isaac **Gym**）+ 200 小时遥操作数据。单臂 Franka。 |
| **AutoMate / Factory / Forge** | 已在 Isaac Lab 仓库内 | 接触密集装配（AutoMate 100 组装配件）。 |

**判断："做一个双臂家具装配 benchmark"这个字面版本，novelty 已经很难主张。**
FurnitureVLA 占了"双臂家具装配 + 仿真数据生成 + VR 遥操作"这一整条；DuoBench 占了
"双 Franka + benchmark + 细粒度失败分析 + 遥操作数据集"；A3D 占了"双臂家具装配仿真环境"。
我们如果按原计划走，会同时踩在这三篇上，而且晚 2~8 个月。

## 3. 但有三个缺口没人占，而且我们已经有实测证据

### 缺口 A：生成数据里的"成功"有相当比例是假的，没人量化过
MimicGen 原论文的机制是"靠环境的 success predicate 过滤，整条任务通过才保留"。
我们实测**这个 predicate 本身是坏的**：Isaac Lab 的 `cubes_stacked` 只验瞬时几何、
不要求方块静止，方块自由落体途中经过"叠好"高度就判成功。两个已交付数据集里
**baseline 28/380（7.4%）、arc 19/358（5.3%）** 的"成功 demo"末帧方块是散的。
另外 `DataGenConfig.max_num_failures` 全仓库 18 处赋值、**零处读取**，自 2023 年
MimicGen 引入 Isaac Lab 起就是死代码。
→ 两个 upstream PR：#7434、#7433（证据见 `docs/mimic_pr_evidence/`）。
→ **这是"大家共用的尺子是坏的"，不是"任务集不够多"。**

### 缺口 B：评测协议的噪声底线没人量化成协议
- 已有最接近的工作是 **SureSim**（[2510.04354](https://arxiv.org/abs/2510.04354)，2025-10），
  但它做的是 **sim↔real 的统计推断**（用少量真机试验校正大规模仿真的偏差，给置信区间），
  **不涉及训练种子方差、checkpoint 收敛方差、数据集间可分辨性**。
- 综述里承认"随机种子能造成 30pp 以上的成功率波动"，但停在抱怨，没变成可执行协议。
- 我们有自己实测的三层噪声（见 CLAUDE.md 2.9）：
  ① 训练不收敛时，**同一次训练相隔 4000 步的两个 checkpoint 闭环成功率差 22.5pp**；
  ② 收敛后，同数据只换训练种子仍有 **±3~4pp**；
  ③ 结论：**"每组训练一次 + 评测 300 次"这个业界标准做法，分辨不了约 7pp 以内的数据集差异**，
  而我们自己就靠它产出过一个 p=0.0011 的假发现，后来作废。

### 缺口 C：把"鲁棒性曲线"当主指标，而不是单点成功率
DuoBench 做了阶段化失败分析，但仍是在固定初始条件下报成功率。
我们已有整套扰动扫描机制（σ 扫描、arc 扫描、同场景配对分析），能产出
"成功率 vs 初始位姿偏差幅度"的曲线，并且已经验证了配对分析怎么做才成立
（per-run 确定性重播种、匹配容差按实测判别间隙定）。

## 4. 由此得出的候选定位（待与用户/老师确认，不是定论）

**路线①（推荐）"装配 benchmark 的测量学"**——不跟 FurnitureVLA/DuoBench 抢
"谁的任务多、谁的策略强"，而是**把它们当被测对象**：现有装配 benchmark 报出来的成功率，
有多少是测量噪声和数据缺陷造成的？交付 = 数据审计工具 + 评测协议实现 + 在双臂家具装配上的实证。
- 优点：主线二的全部工作直接变成方法学章节和第一批证据；两个 upstream PR（一个已合并）
  是"我们发现的 bug 是真的、NVIDIA 接受了"的硬背书；老师要的"工具"落得实。
- 风险：测量学/负面结果类论文在主会不如"新方法新 SOTA"好中（benchmark/dataset track 和
  workshop 对口，FurnitureBench 本身就是 RSS）；且必须在**多个任务、多个策略**上证明，
  否则会被批"只在一个叠方块任务上"。这是主要工作量。

**路线②"双臂 MimicGen"**——Isaac Lab 的 15 个 mimic env 一个双臂都没有，把 MimicGen
扩到双臂协调（一臂扶持、一臂装配）+ 家具装配任务。
- 优点：工程贡献明确、工具性最强、能直接用上已打通的 VR 遥操作。
- 风险：研究新意弱（FurnitureVLA 已有自己的 bimanual data-gen 流水线，只是没开源）。

**路线③"跨 embodiment"**——用手上的 G1/G2、RealMan 双臂、Franka 做跨本体刻画。
- 优点：跨本体比单机器人单任务硬。
- 风险：规模和时间线大得多。
