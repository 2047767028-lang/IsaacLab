# 核心问题核查：有没有人已经开源了完整的仿真资产？（2026-09-04）

> 问题："IKEA-Manual → Manual2Skill → Manual2Skill++ → AssemblyBench 这条谱系，
> 是不是已经把完整的仿真资产开源了？是不是有人已经做出我们想做的东西了？"
>
> **结论：没有。整条谱系开源的都是"几何 + 标注 + 代码"，没有一家开源了
> "能在物理引擎里真正装配起来的资产"。**
>
> 核查方法：不看论文自述，直接用 GitHub API / Zenodo API 枚举仓库和数据集里的**实际文件类型**。
> AssemblyBench 的 4.3 GB 数据集用 HTTP Range 请求读 zip 中央目录，未下载全量。

## 1. 逐个核查结果

| 项目 | 许可 | 开源了什么 | **有没有仿真资产** |
|---|---|---|---|
| **IKEA-Manual**（NeurIPS 2022） | **无 LICENSE 文件** | 754 个 `.obj` 零件 + 连接关系 + 装配树 + 221 页说明书 + 实验代码 | ❌ 只有 `.obj` 裸网格。无配合特征、无碰撞体、无质量摩擦、无 URDF/USD |
| **Manual2Skill**（RSS 2025）<br>`owensun2004/Manual2Skill` | Apache-2.0 | 432 个文件：**204 json / 110 txt / 70 py / 4 blend** | ❌ **网格文件只有 2 个**：`cube.obj` 和一个工具文件。**没有任何家具资产** |
| **Manual2Skill++**（2025-10） | — | **未找到公开代码仓库** | ❌ 论文里的 Isaac Lab benchmark（SUNDVIK 椅 / VASSKAR 架 / LEGO / 飞机模型）**未见资产发布** |
| **AssemblyBench**（CVPR 2026, MERL）<br>`merlresearch/AssemblyBench` | 代码 **AGPL-3.0**<br>数据 **CC BY-SA 4.0** | 代码：183 文件（88 py），网格只有一个渲染用的 `arrow.obj`<br>数据：Zenodo 4.3 GB | ⚠️ 见下 |
| **FurnitureBench**（RSS 2023） | **MIT** | **43 个 URDF + 40 OBJ + 10 USD**，零件按装配单元拆分 | ✅ **唯一一个有仿真就绪资产的**，但玩具尺度、只有 9 件家具、Isaac Gym 时代 |
| **IROS 2026 挑战赛** | — | "与现场一致的高保真仿真环境" | ⚠️ 只给报名队伍，**未开源**；且只有 1 张 UTTER 桌 |

## 2. AssemblyBench 数据集的精确构成（HTTP Range 读 zip 目录得到）

- 远端大小 **4.30 GB**，**600,372 个条目**
- 文件类型分布：

| 类型 | 数量 |
|---|---|
| `.png`（说明书图 / 渲染图 / mask / arrow 图） | **453,060** |
| `.obj`（零件网格） | **37,374** |
| `.ply`（点云） | **37,374** |
| `.json`（标注） | 33,472 |
| `.pt`（torch 张量，装配轨迹） | 5,578 |
| `.ckpt`（模型权重） | 4 |

- 2,789 个装配体（train 2231 / val 278 / test 280），零件数 2~20，平均 6.7

**关键：`.usd` 0 个，`.urdf` 0 个，`.mjcf`/`.xml` 0 个。**
它有"物理可行的 6-DoF 装配轨迹"（`.pt`），但那是**轨迹数据**，不是**可仿真的物理资产**。

另外两条限制：
- **是工业件，不是家具**（industrial objects）
- **是合成的**（synthetic），由 `Assemble-Them-All`（MIT CSAIL）的流水线生成
- 数据 **CC BY-SA 4.0**、代码 **AGPL-3.0** —— 两个都有传染性，用了会污染我们的发布许可

## 3. 结论：缺口非常清晰

从"几何"到"能在物理引擎里装配"，中间这四道工序**没有任何一家做完并开源**：

| 工序 | 谁做了 |
|---|---|
| 零件几何分解 | ✅ IKEA-Manual（102 件）、AssemblyBench（2789 件工业件） |
| 连接关系 / 装配顺序标注 | ✅ IKEA-Manual、AssemblyBench |
| **配合特征（榫卯 / 销孔 / 螺纹几何）** | ❌ **无人**。IKEA-Manual 论文明说 "we do not model connectors" |
| **物理属性（碰撞体 / 质量 / 摩擦 / 惯量）** | ❌ **无人**（FurnitureBench 有，但只有 9 件玩具尺度） |
| **仿真格式（USD / URDF）** | ❌ **无人**（同上） |
| **真实尺度标定** | ❌ **无人** |

**这道工序之所以空着，正是因为它是人力活而不是算法活** —— 跟上一份调研的结论完全一致。
而这恰好是有团队的实验室能做、单人研究者做不了的事。

## 4. 对方案的影响

**没有人做出我们想做的东西。** 但要诚实地限定这句话的范围：

- 我们**不能**再声称"第一个做家具装配数据集"——IKEA-Manual 2022 年就做了几何和标注
- 我们**能**声称的是：**第一个把真实家具变成可在物理引擎中装配的资产库 + 任务集**
  （带配合特征、物理属性、USD、真实尺度）

**可复用的输入**（省掉大量人力）：
- IKEA-Manual 的 **102 件零件分解 + 连接关系 + 装配树** → 任务定义层（**许可待确认，阻塞**）
- FurnitureBench 的 **43 个 URDF**（MIT）→ 流水线打通的第一批，零许可风险

**必须避开的**：
- AssemblyBench 数据 CC BY-SA 4.0 / 代码 AGPL-3.0 —— 传染性，除非隔离否则不要引入
- IKEA 官方 5 件 CC BY-NC-SA —— 同理
