## 一、原始主张，以及它到底在赌什么

设计文档（`docs/接触锚定扰动增广_设计记录.md`）的主张：

> DP/ACT 这类模仿学习策略，对「视觉伺服交接给它那一瞬间的初始位姿偏差」有一个容忍边界。
> 在 MimicGen 生成时给自由空间段加位姿扰动、接触段完全冻结，可以刻画这个边界。

这个主张暗含**两层独立的赌**，必须分开算账（用户 2026-08-21 明确定义过）：

- **第一层（门槛）**：加了扰动，生成出来的数据还是不是"好数据"？
  即生成成功率不崩、留下的每条演示仍真实通过任务判据。
  **这一层只证明"没亏"，不能证明"更好"。**
- **第二层（真正的假设）**：这批数据喂给策略训练，训出来的策略是不是**真的更鲁棒**？

历史上多次出现的错误是**拿第一层的结果去说第二层的话**。第一层的 σ 扫描曲线很漂亮
（σ=0~0.4 平台区 36~37%），但它跟"策略更好"没有任何逻辑关系。

**另一个必须记住的定位**：这个方向**不是全新的**（HumanoidMimicGen 已经验证过"生成时加噪声
提升下游策略"这个大方向）。所以卖点从一开始就不是"发明了新方法"，而是设计文档里说的
**"用它量，不卖它"**——产出应该是"刻画了失效边界的形状"。这条定位决定了：
**即使第二层是负结果，只要边界刻画得清楚，工作仍然成立。** 这不是事后找补，是原定的框架。

## 二、信念是怎么变的（这是本文件的核心）

### 阶段 0：假设——扰动增广会让策略更鲁棒

推理：更多轨迹多样性 → 策略见过更多状态 → 对初始偏差更宽容。
这个推理**在当时看不出毛病**，问题出在"多样性"这个词太笼统（见阶段 4）。

### 阶段 1：第一次测量说"有害"

baseline 81.0% vs arc 69.7%，差 −11.3pp，McNemar 配对检验 p=0.0011。

信念更新：假设可能是**反的**——扰动不是让策略更鲁棒，而是损害了它。
当时还给出了一个自洽的机制解释（鲁棒性-精度权衡的成本端）。

**这一步的推理没错，错在没有质疑测量本身。**

### 阶段 2：质疑测量 → 发现训练从未收敛

追问链条是这样展开的：

1. 先怀疑 **horizon 截断**（所有失败都是跑满 400 步）→ 实测否定：成功轨迹 p95 仅 299 步，
   放宽到 1200 步后 6 次成功全在 242 步内完成，2 次失败跑满 1200 步仍失败。
   **失败是策略卡住，不是时间不够。**
2. 用户提出**训练量可能不够** → 查 loss 曲线 → 发现 `peak_lr == decay_lr`，
   余弦退火退化成恒定学习率，全程无 warmup、峰值是官方默认的两倍。
3. 决定性证据：**同一次训练、同一批数据，step 16000 与 19999 的闭环成功率差 22.5pp**
   （58.5% vs 81.0%，置信区间完全不重叠）。

**信念更新：阶段 1 的结论作废。** 训练内部波动（22.5pp）是被当作结论的数据效应（11.3pp）
的两倍——那个 p=0.001 是随机游走上两个采样点之差。

⚠️ **这一步最值得记住的不是"学习率配错了"，而是"一个静默的超参错误可以伪造出统计显著的
科学结论"。** CLAUDE.md 2.7 节当时已经写下了正确做法，但没落实到训练脚本里。

### 阶段 3：修好训练 → 效应缩小且消失

修复退火后重训（`param_norm` 末段/首段从 0.989 降到 0.069，权重确实落定了）：

```
v1（未收敛）          −11.33 pp   p=0.0011
v2, n=109             −8.26 pp    p=0.211
v2, n=193             −6.22 pp    p=0.201
v2, n=300（跑满）     −5.33 pp    p=0.167
v2, 两种子平均        −1.83 pp    95%CI [−7.11, +3.45]
```

**信念更新：既测不出有害，也测不出有益。** 点估计随着两件事持续向 0 漂：
修好训练收敛，以及增加样本量/种子平均。这个漂移模式本身就是"真实效应很小或不存在"的特征。

### 阶段 4：机制——为什么本来就不该有效果

用户提出的前提是「arc 扰动本质是模拟人类采集时的路径变化」。**这个前提经实测不成立**，
而且差在最要紧的维度：

| | 人类演示 | arc 实现 |
|---|---|---|
| 方向 | **强方向性**：subtask3 十条全部向上，仰角 +47~+67°，R=0.850（各向同性时中位数 0.285，p<0.0001） | `torch.randn(3)` 归一化，**各向同性随机，约一半时间往下扰** |
| 幅度 | 自然弯曲 4.8~9.3cm；跨演示残差 2.8~4.6cm | 峰值 1.2cm |

**最关键的一步推理**：人类那个向上的弧线**不是"扰动"，它就是策略本身**——抬起来绕过去是
完成任务的正确方式。而 MimicGen 照搬源演示的路径形状再做位姿变换，**这个抬升本来就完整
保留在 baseline 数据里**（实测 144 条生成数据 98.6% 仍向上，仰角均值 +55.0°，对源演示的 +58°）。

**所以本实验真实的对照关系是**：

```
不是   「MimicGen 数据」 vs 「人类风格数据」
而是   「MimicGen 数据」 vs 「MimicGen 数据 + 各向同性随机噪声」
```

在这个框架下，"没有效果"是**预期之内**的，甚至"轻微有害"也说得通：
我们在一条已经带有正确 9cm 抬升弧线的轨迹上，叠了 1.2cm 的、方向随机的、
**观测里看不出来的**扰动。对模型而言那是分叉点上的标签噪声。

⚠️ 用户提过一个反驳值得记住：**MimicGen 已经让轨迹随物体位姿自适应，arc 只是在此之上再加
一个特征**。这个反驳是对的，我原先的措辞（"变化和观测无关"）不准确。精确版本是：
**基础轨迹 = f(场景) 是一对一映射；arc 把它变成一对多，新增的那一项不可从观测预测。**
这个更正让论证更锋利，不是推翻它。

### 阶段 5：噪声底线——这次实验真正的分辨率

同一批数据只换训练种子重训：baseline −3.67pp（p=0.359），arc +3.33pp（p=0.440）。
**两个都不显著**，所以严格表述是**训练噪声 ≤ 约 4pp**，不能说"已测得噪声为 3.5pp"。

最有说服力的排列：

```
arc      种子777   68.67%   ← 两个 arc
baseline 种子42    70.67%
baseline 种子777   67.00%
arc      种子42    65.33%   ← 夹住两个 baseline
```

**换个训练种子，arc 就从"比 baseline 差 5pp"变成"比 baseline 好 1.7pp"。**

## 三、当前信念清单（按置信度分层）

### 确信（有直接实测支撑，可以拿去写）

- v1 那个 −11.3pp / p=0.001 的"有害"结论**作废**，来源是未收敛训练的随机波动。
- 修好退火后训练确实收敛（五次训练 `param_norm` 末段/首段全部落在 0.068~0.073，
  末 1000 步 loss 斜率 |t|<2）。
- **单次训练的组间对比在这个任务上不可信**——不收敛时单次训练内就有 22.5pp 波动，
  收敛后换种子仍有 ±3~4pp。
- arc 扰动**不是在模拟人类路径变化**（方向性和幅度都对不上，有度量支撑）。
- MimicGen 位姿变换**不会**把人类的抬升转歪（全部 subtask 的 object_ref 方块
  roll/pitch ≤ 0.014°，变换退化为纯绕世界 Z 轴旋转，Z 分量精确保留）。
- 评测环境的方块随机化与生成训练数据时**完全一致**（同一个配置对象，代码层面可证）。
- `--seed` 钉的是"一串各不相同场景"的可复现序列，不是单个场景 → **多 seed 评测不增加
  统计效力**（5seed×60 等价 1seed×300）。

### 倾向相信（证据一致但不够硬）

- 扰动增广数据在这个任务上**既不有害也不有益**，真实效应若存在则小于约 7pp。
- 之所以没效果，是因为加的是**任务无关、观测不可预测的各向同性噪声**，
  而且幅度（1.2cm）远小于数据里本来就有的任务相关多样性（物体位置驱动的 20cm 量级）。

### 悬而未决（不要当结论用）

- **mixed 组的 −10.00pp（p=0.0078）**是全研究唯一显著的对比，但**只有一个训练种子**，
  而已知种子波动 ±3.7pp。第二个种子（777）训练中。
  - 若成立：方向是"混合比两个纯数据集都差"，与阶段 4 的机制假设自洽
    （混合会在同一场景上制造"直行 vs 鼓包"两个互斥标签，冲突比纯 arc 更强）。
  - 若不成立：那么三组全部无差异，结论更干净。
- 训练预算被 12 小时窗口压到 10000 步（退火同步压缩所以收敛，但总量只有一半）。
  **更长训练是否改变结论，没测过。**

## 四、活跃的推理线索（下一步可以接着推的地方）

### 线索 A：如果要救这个方向，扰动应该长什么样

阶段 4 的度量直接给出了可实现的设计：**沿人类实际变化的方向扰动，而不是各向同性**。
数据摆在这——人类变化集中在仰角 **+47°~+67°** 的锥形里，幅度 **5~9cm**。

但要诚实：这会是**第三版**扰动机制，而前两版（起点扰动、arc）都已经走完。
**投入前应该先回答：第三版的成功判据是什么？** 如果仍然是"闭环成功率提升"，
那按噪声底线，需要每组多个种子 + 更大样本才可能测出来——成本很高。

### 线索 B：MimicGen 生成失败归因打开了另一扇门

1050 次生成只有 36% 成功，此前无人分析。已经查明：

- **56%**：抓起红块但没叠上蓝块。末帧距离呈**双峰**（1~2cm 叠上 / 5~6cm 滑到旁边，
  约一个边长），3~4cm 谷底全场仅 5/1050 → 判据阈值没问题，是真实物理失败。
  **但"为什么 45% 的放置会偏出 3cm 以上"机制未知。**
- **28%**：红块叠好了，第二次抓取整个失败（绿块纹丝未动、13.9cm 外）。**这是另一个模式，
  没查过。**
- **11%**：判据误杀——夹爪容差仅 ±0.104mm，实测停在差 1.2mm 处但方块已松开。
  放宽到 3mm 可回收 71%，**生成产出约 +5pp**。这是个现成的、便宜的改进。

已经否掉的假设：抓取偏心传导（r=0.045/0.128，只解释 0.2~1.6% 方差）；
方块摆放位置预测成败（1050 样本上所有 |t|<2.1，排除可达性解释）。

**这条线索的吸引力在于：它是 MimicGen 的真实缺陷，修它是实打实的贡献，
而且和"加扰动"是完全不同、更有说服力的故事。**

### 线索 C：方法学结论可能才是最硬的产出

> 用"每组训练一次 + 评测 300 次"这种标准做法，在这个任务上无法分辨约 7pp 以内的数据集差异
> ——而绝大多数同类工作正是这么做的。

三条证据构成闭环：不收敛时单次训练内 22.5pp 波动 → 收敛后换种子仍 ±3~4pp →
种子平均把表观效应从 −5.33pp 压到 −1.83pp。

这条结论**不依赖 arc 有没有效果**，而且直接对应设计文档"用它量，不卖它"的定位。
**如果最终要写成东西，我倾向认为这是主线，扰动增广是案例。**

### 线索 D：原始研究问题其实还没被真正回答

注意一件事：**第二层验证测的是"零扰动下的成功率"，而原始假设讲的是"对初始位姿偏差的容忍边界"
——那是一条曲线的斜率，不是一个点。**

我们测了截距，没测斜率。真正对应假设的实验应该是：在**一组递增的初始位姿偏差**上分别评测
两个模型，看谁衰减得慢。评测脚本的 `--reset_joint_std` 参数就是为此准备的（已实现）。

**但这条路有个已知的批评**（用户自己提出的，很到位）：**"随机化机械臂初始位姿"在真实评测里
几乎没人用，赢了也没有应用出口，而且我们在生成时加了扰动、再用带扰动的条件去测，
是循环论证。** 这个批评没有被解决，只是被搁置了。

如果要重启这条线，必须先回答：**这个评测轴的应用出口是什么？**
（可能的答案：sim-to-real 时的标定误差、视觉伺服交接精度、外部扰动恢复——但都需要论证。）

## 五、已经走过的死路（别再走）

1. **物理瞬移做扰动**（commit `5a813b3eb`，已 revert）：`write_joint_state_to_sim` 是纯运动学
   瞬移不经过物理步进，**手里抓着的方块不会跟着走，等于凭空脱手**。
2. **离散控制点 + 直线插值的弧线**（commit `0d2d676a2`，已 revert）：控制点处有真实的方向硬
   转折（实测单帧 116.9° 转向，基线同帧 29.8°）。密度和幅度不独立，不能做二维网格扫描——
   直接把密度推到每帧才根除这个问题。
3. **延长 horizon**：已验证无效，失败是策略卡住不是时间不够。
4. **靠堆评测样本量解决**：噪声在训练端不在评测端。噪声底线 ±4pp 的情况下，
   把评测做到 n=1485 也没用，正确做法是每组多个种子。

## 六、推理陷阱清单（元层面，这次会话真实踩过的）

这些不是项目叙事，是**下次推理时会再犯的错**：

1. **拿两个点估计直接比大小当判定**。我曾写下"−5.33pp > 噪声底线 3.67pp，故超出噪声"，
   这是错的——两个数各自都有不确定性，而且那两个种子差异本身都不显著。
2. **把部分样本的数字当稳定结论报出去**。arc 换种子的差异在 n=101 时是 +9.9pp，
   跑到 n=300 变成 +3.3pp。**n<150 的中间结果不要拿去做判断。**
3. **只看"启动成功"就报告"任务在跑"**。一次把 OOM 崩溃 18 秒的训练当成"已跑 4 小时"。
   **解法**：查进度计数是否增长 + GPU 利用率 + 进程 CPU 时间，三者交叉。
4. **用错误的日志格式 grep 导致误判"卡死"**（实际正常）。报警前先确认探针本身对不对。
5. **复现一个判据后不先在已知正例上验证就拿去用**。第一版 `cubes_stacked` 复现在成功样本上
   0% 通过（`gripper_pos` 第二根手指是取负存储的）。**先在成功文件上验证 100% 通过再用。**
6. **读配置字段的文档字符串当作实际行为**（`max_num_failures` 那次：18 处赋值但从未被读取）。
7. **相信"两个 AI 都觉得没问题"**。子 agent 和主 agent 共享同类失效模式，
   它的定位是唱反调的第三方视角，不是事实核查工具。

## 七、什么证据会改变现在的结论

诚实列出来，避免下次陷入"找证据支持已有结论"：

| 若观测到 | 则结论变为 |
|---|---|
| mixed 第二个种子仍显著低于 baseline | arc 数据在混合时**确实有害**（与阶段 4 机制自洽），这是个可写的正结果 |
| mixed 第二个种子回到 baseline 水平 | 三组全部无差异，结论更干净，扰动增广在此任务上**无影响** |
| 每组训 5 个种子后 arc 仍稳定低 2~3pp | 存在真实但微弱的有害效应，值得单独讨论 |
| 方向性扰动（+47~67° 锥形，5~9cm）训出的策略明显更好 | 阶段 4 的机制假设被证实，**方向匹配才是关键变量** |
| 20000 步训练下差异重新出现 | 当前结论受训练预算限制，需重做 |

## 十、三个新测量，把"为什么没效果"从一条理由变成三条

第四阶段给的解释是"arc 是各向同性噪声、不像人类变化"。那条仍然成立，但它只是**第二位**的理由。
这次测出来的三件事说明：**这个实验从结构上就测不出东西**，跟 arc 是不是各向同性关系没那么大。

### 10.1 实际加进去的扰动，比"1.2cm"这个说法小 3 倍

`PERTURB_ARC_STD=0.012` 一直被口头称作"1.2cm 扰动"。但 1.2cm 是**自由区正中央单帧的峰值**，
不是平均位移。按 `_apply_arc_perturbation` 的实际公式（order=6, peak_frac=0.5）算：

| 量 | 数值 |
|---|---|
| 包络在自由区上的均值 | 0.4569 |
| 自由区占 subtask 帧数（freeze_frac=0.3） | 70% |
| **整条 subtask 的平均位移** | **1.2 × 0.4569 × 0.70 = 0.38 cm** |
| 自由区内平均位移 | 0.55 cm |
| 峰值位移 | 1.2 cm（只有中间那一帧） |

对照 §2.9.5 实测的人类演示自然变化（跨演示残差离散度 2.83cm / 4.61cm）：
**arc 的平均位移只有它的 8~14%。**

⚠️ 口径说明：0.38cm 是平均模长，2.83cm 是残差离散度（标准差量级），两者定义不完全对等，
上面的百分比是量级比较不是精确比值。但差一个数量级这件事不受口径影响。

### 10.2 连 v2 大扫描的上限也没够到"能起作用"的量级

同一个公式往回代 v2 正式扫描的最大幅度 3.0cm：平均位移 = 3.0 × 0.4569 × 0.70 = **0.96cm**，
仍只有自然变化的 21~34%。

**这直接解释了 §2.9 那句"3.0cm 处仍在下降，没摸到塌陷后企稳的平台"**——当然没摸到，
整个 15 点、37500 次尝试、4.9 小时的扫描，**根本没进入"扰动量级可与数据自身变化相比"的区域**。
那不是网格没铺够，是网格铺错了地方。

### 10.3 接触段逐字节相同——已在代码里确认，不再是"设计意图"而是事实

`data_generator.py` 的 `_apply_arc_perturbation` 最后一行：

```python
new_poses[:free_len, :3, 3] = poses[:free_len, :3, 3] + offset   # free_len = round(T * 0.70)
```

只写前 70% 帧，**每个 subtask 末尾 30%（最靠近接触点那段）与 baseline 逐字节相同**，
再加上包络两端数值和导数都精确为 0。这正是"接触锚定"的设计本意，但它有个此前没点破的推论：

> **arc 按设计影响不到接触段。而叠方块的成败几乎完全由接触段精度决定
> （抓取偏心、放置偏差——§2.9.6 的失败归因里 56%+11%+3% 都是接触段的事）。
> σ=0 的评测又让策略从训练时完全相同的标称起点出发、沿标称流形运行。
> 三者叠起来：我们把测量放在了 arc 按设计就碰不到的那个轴上。**

所以 **σ=0 处的零效应，不是"方法无效"的证据，而是"这个测量轴看不见这个机制"的证据。**
这跟"arc 真的没用"是两个不同的命题，不能混着说。

## 十一、评测这把尺子本身：逐场景配对分析（全新，此前没人做过）

五组评测共用 `--seed 101`，跑的是**同一串 300 个场景**，所以可以逐场景配对。以前只看合并成功率，
把这层信息浪费掉了。

### 11.1 场景难度几乎不决定成败

| 几个模型成功 | 场景数 |
|---|---|
| 0/5（全员失败） | 5 (1.7%) |
| 1/5 | 16 (5.3%) |
| 2/5 | 51 (17.0%) |
| 3/5 | 85 (28.3%) |
| 4/5 | 91 (30.3%) |
| 5/5（全员成功） | 52 (17.3%) |

**81% 的场景上五个模型有分歧。** 两两一致率 54.7~61.0%，而独立假设下的期望一致率是
53.3~57.7%——**实测只比"完全独立"高 −1.1 ~ +5.6 个百分点**。

置换检验（20000 次，打乱各模型的成败向量）：实测 k 方差 1.4255，零分布均值 1.1086
（95% 区间 [0.952, 1.272]），**经验 p = 0.0001**。所以场景效应**存在但很弱**：
统计上显著，量级上只比随机高几个百分点。

⚠️ 这一条同时废掉一个此前的说法：CLAUDE.md §2.9.2 说两模型共用 seed 是"为了配对比较、
消掉某些摆放本身就难的方差"。**实测配对相关系数 phi 只有 −0.02~+0.13，配对几乎没消掉任何方差**，
McNemar 相对非配对检验拿不到效力增益。共用 seed 仍然该做（不共用只会更差），但别指望它。

### 11.2 同数据、只换训练种子 → 四成场景结果相反

| 对比 | 逐场景不一致 | 净成功率差 |
|---|---|---|
| arc s42 vs s777 | **136/300 = 45.3%**（A赢63 / B赢73） | −3.33 pp |
| baseline s42 vs s777 | **119/300 = 39.7%**（A赢65 / B赢54） | +3.67 pp |

**同一批数据训出来的两个模型，在 40~45% 的单个场景上给出相反结果，净成功率却只差 3.5pp。**
巨大的逐场景翻转，相互抵消后只剩很小的净差。这就是 ±4pp 训练噪声底线的微观机制。

### 11.3 机制找到了：pi0.5 推理本身是随机的，而且 RNG 流跨 rollout 推进

不用烧 GPU，读 `openpi/src/openpi/policies/policy.py` 就能确认：

```python
self._rng = rng or jax.random.key(0)                 # 建服务器时固定成 key(0)
...
self._rng, sample_rng = jax.random.split(self._rng)  # 每次 infer 都推进状态
result = self._sample_actions(sample_rng, ...)
```

两个推论：

1. **策略是随机采样的**（flow matching），不是确定性的。
2. **RNG 状态在整个 server 生命周期里累积推进**，而 rollout 长度不等（成功约 255 步、失败 400 步），
   所以**第 k 个 rollout 拿到的噪声取决于前 k−1 个 rollout 的总步数**——实际上是任意的。

这就完整解释了 11.1 的近随机一致率：每个模型在场景 i 上的那一次 rollout，
带着一个实际上任意的采样 draw。**场景难度的信号被采样噪声压在下面。**

⚠️ 这**不影响**合并成功率的有效性——每次 rollout 仍是独立伯努利试验，n=300 的 Wilson 区间
（±5pp）已经把采样随机性算进去了。它影响的是**逐场景层面的一切解读**。

⚠️ 副作用提醒：因为 server 重启会重置到 `key(0)`，同一模型同一场景序列重跑会**逐位复现**。
所以"跑两遍看重复性"测不出策略的随机性，要测必须给 server 传不同的 rng key。

## 十二、把三条并起来，结论是什么

三个**互相独立**的结构性原因，任何一个单独成立都足以让效应测不出来：

| # | 原因 | 证据 |
|---|---|---|
| 1 | **干预量级不够**：平均只加了 0.38cm，是数据自身变化的 ~10%；连扫描上限 3.0cm 也只到 21~34% | §10.1 / §10.2 |
| 2 | **测量轴错了**：arc 按设计不碰接触段，而成败由接触段决定；σ=0 又让策略沿标称流形跑 | §10.3 + 代码 |
| 3 | **仪器分辨率不够**：逐场景结果被策略采样随机性和训练种子主导，场景效应只比随机高几个 pp | §11 |

**所以"扰动增广没效果"这个说法要改口径**：目前测到的是"**在一个量级不够、轴不对、
分辨率也不够的实验里没测出效果**"，不是"这个方法没用"。这两句话在写报告时的分量完全不同。

## 十三、线索 D 的两个批评，一个被推翻，一个可以化解

第八节问题 3 问"线索 D 的应用出口能不能论证清楚"。现在可以正面回答。

### 13.1 "循环论证"这条批评——**事实上不成立，已实测否掉**

原批评：生成时加了扰动、再用带扰动的条件去测，是循环论证。

**实测**（本地 hdf5，两组各读全部 demo 的首帧）：

| | 首帧 7 个臂关节 joint_pos 跨 demo 标准差 | 首帧 eef_pos 跨 demo 标准差 | 对照：首帧方块位置 |
|---|---|---|---|
| baseline (N=380) | **精确 0.0**（七个全是） | 4.8e-7 / 2.2e-7 / 3.1e-7 m | 有真实散布 |
| arc_1p2cm (N=358) | **精确 0.0**（七个全是） | 4.4e-7 / 2.2e-7 / 3.1e-7 m | 有真实散布 |

EEF 散布 1e-6 米量级 = 纯数值噪声。加上 §10.3 的包络端点约束（subtask 1 的起点不被扰动），
**两组训练数据都不含任何初始位姿扰动**。

所以用 `--reset_joint_std > 0` 评测，对**两个模型都是同等的分布外泛化测试**，
是 train-on-X / test-on-Y，不是 train-on-X / test-on-X。**循环论证的批评不成立。**

### 13.2 "没有应用出口"这条——化解方式是换定位，而不是硬找应用

原批评：随机化机械臂初始位姿在真实评测里几乎没人用，赢了也没有应用出口。

三个能站住的应用场景（按强度排）：①**分阶段流水线的交接误差**——粗定位/视觉伺服把手臂带到
工作区附近再交给学习策略，交接位姿必然有误差，这正是设计文档最初的原话"视觉伺服交接给它
那一瞬间的初始位姿偏差"；②**中断后重新接管**（安全停机、人工介入后恢复）；
③sim-to-real 的 home 位姿复现误差（较弱，真实标定误差远小于厘米级）。

但更该说的是第四种回答：**它根本不需要是"应用"，它是把尺子。** 本项目自己定的定位就是
"用它量，不卖它"——初始位姿扰动的作用是**度量策略的能力边界能延伸出演示流形多远**，
就像图像鲁棒性研究用人造 corruption 当标尺一样，没人要求部署时真去加高斯噪声。
**按这个定位，"没有应用出口"不是缺陷，是类别错误。**

## 十四、但是——线索 D 大概率也测不出 arc 的差异，而这本身是结论

必须诚实说清这个两难，否则又会重蹈"投了算力才发现测不出"的覆辙：

- arc 教给策略的是 **平均 0.38cm** 的偏离路径经验（§10.1）。
- 评测网格里最小的 σ=0.02 对应末端位移约 **1.7cm**（按 §2.1 实测 σ=0.2→17.3cm 线性外推，
  约 0.865 cm / 0.01 rad），已经是 arc 教过量级的 **4.5 倍**。
- 要压到 arc 教过的量级（≤0.5cm）就得 σ≤0.006，那里成功率大概率根本不掉，没有分辨力。

> **两难：σ 小到 arc 教过的范围内 → 没有动态范围；σ 大到能看出差异 → 早已超出 arc 教过的范围。**
> 这个两难本身就说明：**峰值 1.2cm 的 arc 扰动，在这个任务上不可能有可测的鲁棒性收益。**
> 不是"还没测到"，是"按这个量级设计就测不到"。

**推论——如果真要做第三版扰动，量级该定多少是可以算的**：要让平均位移达到自然变化量级
（约 2.8cm），需要峰值 = 2.8 / (0.4569 × 0.70) ≈ **8.8cm**。而 v2 扫描在峰值 3.0cm 处生成成功率
已降到 19.1%，8.8cm 处只会更低。**"要让扰动大到有意义，就得付出生成成功率塌陷的代价"——
这句话本身就是设计文档要的那个"失效边界的形状"，而且它是算出来的，不是猜的。**

## 十五、下一步：先测边界，别再先测对比

### 15.1 为什么顺序要反过来

原本的计划是"在一组递增扰动上分别评测两个模型，比谁衰减得慢"。按 §14，这大概率又是一个零结果，
而且要 4 个模型 × 多个 σ × n=300，成本 24~64 小时。

**改成：先只用一个模型（baseline_s42）测出衰减曲线本身。** 理由四条：

1. **成本是对比实验的 1/4**（一个模型而不是四个）。
2. **它一定有结果**——曲线一定会下降，不像对比实验大概率给出又一个零效应。
3. **它就是产出物本身**。项目定位是"刻画失效边界的形状"，这条曲线就是那个形状，
   **它的成立不依赖 arc 有没有用**。
4. **它是设计对比实验的前提**。不知道曲线在哪段下降，就不知道该在哪些 σ 上做对比；
   现在盲铺网格，大概率把预算花在曲线的平坦段或地板段上。

### 15.2 具体方案（成本已核实，可直接执行）

- **模型**：`baseline_s42`（checkpoint 已在服务器，step 9999，无需重新训练——四个 v2 checkpoint 全在，
  `openpi_smoke_checkpoints/` 下 baseline/arc 各两个种子，磁盘余量 1.5T）
- **网格**：σ ∈ {0.02, 0.05, 0.10, 0.20}，对应末端位移约 {1.7, 4.3, 8.7, 17.3} cm。
  σ=0 已有 n=300 的现成点（70.67%）
- **每点 n=100**（此阶段只为定位拐点，不做组间判定，±10pp 够用）
- **成本**：4 点 × 100 次 × 46 s ≈ **5.1 小时**，一个通宵
- **前置**：必须等 mixed_s777 的流水线跑完（它会占 GPU0 做 policy server + GPU3 跑 Isaac Sim）

⚠️ **成本前提**：46 s/rollout 是**机器空闲时**的实测值（baseline_s777 3.87h/300、arc_s42 4.06h/300）。
被其它任务抢占时会掉到 134~143 s/rollout（11~12h/300）——五组评测里有三组是在被抢占状态下跑的。
**推理耗时恒定 25~28 s/rollout，差异全在仿真侧。** 所以排期要挑机器空的时候。

### 15.3 必须先做的一个零成本改动

现在有 1500 次 rollout 的评测数据，但**一句话都说不出失败发生在哪**——记录里只有
`success / outcome / steps / wall / infer`，没有任何场景状态。§2.9.6 给生成阶段做了完整的失败
归因，评测阶段完全是空白（§2.9.7 那句"策略卡住"是 n=8 得出的）。

**改动**：在 `play_policy_server.py` 的 rollout 记录里加上末帧的 `cube_positions` / `eef_pos` /
`gripper_pos`。不改变 rollout 动力学，不影响与已有五组评测的可比性，成本为零，
但让**此后每一次评测都能自动做失败归因**。

⚠️ 时机：**必须等 mixed_s777 的评测进程启动之后再改**。现在改，万一有语法错，
会毁掉已经等了 5 小时训练的那次评测。评测进程一旦启动，Python 已把文件读进内存，改文件不影响它。

"arc 按设计影响不到接触段"——严格说成立的是：**目标位姿序列**在每个 subtask 末尾 30% 与 baseline
逐字节相同（`new_poses[:free_len]` 只写前 70% 帧）。**实际执行状态**理论上仍可能有微小差异，
因为机械臂是从一条不同的自由空间路径接近过来的，differential IK 的跟踪残差未必完全一致。
但由于末尾 30% 一直在跟同一串目标收敛，到接触时刻残差应已基本收敛。

这个区别不影响 §12 的结论（三条原因里第 2 条讲的是"测量轴"而非"绝对不可能有任何影响"），
但写正式产物时该用"目标轨迹逐字节相同"这个可直接验证的说法，而不是"完全不影响"。

# 第三轮推理（2026-08-30）：「接触段冻结」被实测推翻

## 十九、这一轮的起点

用户提出：`sin²` 包络首末斜率为零、接触段冻结，所以接触不该出错，成功率还是暴跌，
**大概率是判据对 arc 组不公平**。

这个质疑值得查，因为它如果成立，v2 扫描的整条曲线都要重新解读。查下来：
**判据没问题，方向反了；但用户的直觉指对了地方——问题确实出在接触段。**

## 二十、方法上的一个意外收获：扫描数据可以逐场景配对

发现 v2 扫描的 per-run seed 让**不同幅度下的场景序列完全相同**——seed1 下 0.5cm 与 3.0cm
的 500 个初始布局逐条匹配到 <1e-6 米（`pair_check.py`）。

这一条把整轮分析的效力提高了一个档次：可以取"**同一场景、两个幅度都成功**"的样本做配对
比较，**场景难度这个混淆因素被彻底消掉**，而且注入的 action noise 也是共模的、在配对差
里抵消掉了（0.6cm 处配对偏差仅 0.18cm 就是证据——若噪声不共模，这个数会是 1.7cm 量级）。

⚠️ 这个手法以后遇到类似扫描都该先试一下：**先查种子是否让场景序列跨条件复现**，
如果是，配对分析几乎免费地把统计效力翻上去。

## 二十一、核心结论（全部实测）

**「冻结的是指令，不是状态」。** 详细数字见 `docs/接触锚定扰动增广_设计记录.md` 的订正节和
`docs/arc_sweep_diagnosis/README.md`，这里只记信念变化：

- 冻结段内目标逐字节相同，实际末端却差 **1.30~1.38cm**（3.0cm 幅度，三 seed），
  **约为幅度的 45%**，线性。
- 机械臂**永远落后目标约 5cm**，只执行指令的约 20%——这是物理限制，官方 MimicGen 也一样，
  它没事是因为"每次都以同样的方式错"。
- 关节构型永久偏移 0.105 rad 且**不衰减**；冻结段内差异每帧只衰减 **0.76%、半衰期 90 帧**，
  而冻结段只有 18 帧 → **不是"尾巴太短"，是环路根本没在纠正它**。
- 残差沿运动方向分量仅 37~41%（各向同性 33%）→ **不是滞后**，方向继承自 arc 的 `randn(3)`。

⚠️ **这一条同时作废了本文件上一节末尾我自己写的那句**："由于末尾 30% 一直在跟同一串目标
收敛，到接触时刻残差应已基本收敛"——实测残差**不收敛**。那句是当时的合理推测，现在有数据了。

## 二十二、被排除的两个"结论杀手"

按纪律记下来，因为它们都差点让整轮分析作废：

1. **末尾对齐可能是假象**：按帧索引从末尾比较，若两次 episode 长度不同就会凭空造出偏差
   （末端 0.405cm/帧，错 3 帧 = 1.2cm，与结果同量级）。实测：**配对 episode 长度 100% 相同**，
   且 ±5 帧任意时移下最优偏差与原值完全一致、最优时移中位数 0。
2. **动作里的噪声可能主导 gain 估计**：`action_noise=0.03` 是每轴 σ=3cm，三轴约 5.2cm，
   而实测动作模长中位数 7.4cm——**噪声占了大头**。所以"等效增益 0.101"是低估，扣掉噪声后
   真实滞后约 5.3cm、增益约 0.14。**报这个数时必须带上噪声修正，否则是错的。**

## 二十三、下一步的分叉

用户提出：既然问题是关节构型错位，那能不能**把冻结从"只冻末端"扩展到"连关节位姿一起冻"**？

方向对，但直接冻关节撞在已知死路上（§五.1：`write_joint_state_to_sim` 是运动学瞬移，
手里的方块不跟着走）。评估见下一节 / 后续对话。

**一个更便宜的候选**：残差之所以不衰减，是因为两次运行都在追**移动**的目标、各自停在不同
稳态滞后上。如果让目标**停住**，闭环就能真正收敛——而 MimicGen 的 `SubTaskConfig` 里
**本来就有 `num_fixed_steps`（"Additional fixed steps for the robot to reach the necessary
pose"），当前设为 0**。按增益 0.14 估算，约 18 帧驻留可把 1.4cm 残差压到 1mm 量级。
这个还没验证，只是从已测的增益推算出来的。

## 二十四、三个候选修法（用户 2026-08-30 提出），及前提检验

### 记录：三个方向

| | 方向 | 隐含假设 |
|---|---|---|
| **一** | 生成 arc 的同时并行跑一组原版 MimicGen，照抄它冻结段首末的**关节位姿**；用几十帧平滑过渡代替单帧瞬移，避免手里方块脱手 | **关节构型**错位是病根 |
| **二** | 把**夹爪位置**归位；或叠加一个始终指向正确轨迹的矢量把它拉回来 | **夹爪位姿**偏差是病根 |
| **三** | **让目标停下来** | 两者都不是根本——差异不消失只因为手臂在追**移动**的目标 |

### 前提检验（离线，用现有扫描数据，不花仿真算力）

在**夹爪第一次闭合那一帧**（= subtask 1 的抓取时刻，也是增长最快的失败模式所在）分组：

| 量（seed1, arc 3.0cm, n=500, 28 次抓空） | 抓起来 | 没抓起来 | Cohen's d |
|---|---|---|---|
| 夹爪到方块距离 | 1.50cm | **3.83cm** | **2.57** |
| 夹爪位置偏差 | 0.72cm | **1.88cm** | **1.35** |
| 关节构型偏差 | 0.034rad | 0.052rad | **0.71** |

直接死因是夹爪闭合时离方块 3.83cm（张开仅 8cm）。

**决定性的一步**——按夹爪位置误差分层，看关节偏差还剩多少**独立**预测力
（4 个幅度合并，n=2000，78 次抓空）：

| 夹爪误差带 | 关节偏差的 d |
|---|---|
| 0.07–0.32 cm | **−0.65**（反向） |
| 0.50–0.75 cm | **+0.24**（约等于无） |
| 0.75–5.15 cm | +0.68（此档跨度过宽，未真正控住夹爪误差） |

**结论：关节构型只是夹爪位置的代理变量。**

### 对方向一的评判：不建议做（三条理由按分量排）

1. **买不到额外的东西。** 恢复关节 ⟹ 必然恢复夹爪位姿（正运动学），所以它是"充分但不必要"
   ——是方向二的一个更贵实现。而分层测量说明夹爪位姿对了之后关节基本不影响抓取。
2. **平滑过渡规避了瞬移死路，但代价没消失。** 分几十帧慢慢挪，方块每帧被拖一点再靠摩擦重新
   咬住，30 帧累积滑移可能到厘米级——**与待修误差同量级**。而且只在夹爪**空着**时安全
   （subtask 1/3 的接近段）；拿着方块的 2/4 仍危险，而放置失败恰是最大类别（约 60%）。
3. **实现代价最高**：并行跑一组 + 两条 RNG 流同步 + 关节参考传进生成循环 + 分帧插值。

⚠️ 但方向一的**可行性前提是成立的**：实测同一 seed 下不同幅度的场景序列完全相同
（500 布局精确匹配），"并行一组当参照"原理上可行。否掉它的是性价比，不是可行性。

### 方向二/三的实测设计

- 方向二 → 提高 `arm_action.scale`（0.5 → 1.0）。注意"叠加指向正确轨迹的矢量"控制器
  **已经在做**（动作就是 `目标 − 当前`），能加强的只有增益。
- 方向三 → `num_fixed_steps` 0 → 20（MimicGen 自带的"发一段不动的目标让机械臂追上"）。

⚠️ 对方向三的保留：`num_fixed_steps` 加在每个 subtask 的**开头**，而抓取在 subtask 的
**结尾**——位置可能不对。但改一个配置项就能试，负结果也有信息。

六组对照（arc 0.05cm 参照 / 3.0cm 惩罚最大处 × 原样 / 驻留 / 增益），各 300 次固定尝试。
结果见下一节。

# 第四轮推理（2026-09-02）：方向二的首次有效实验，与我重复犯错的记录

## 二十五、结论先行

**方向二（靠拢平行组实际位姿）测出来是负的，但这个负结果不算数**——因为我在实现里犯了和
第三轮刚刚诊断出的**同一类错误**。详细数字见 CLAUDE.md 2.13，这里记推理。

## 二十六、我怎么又犯了同一个错

第三轮的核心发现是：MimicGen 重放**目标位姿**，手臂落后目标约 5cm，**复现这个落后量才复现
动作**。我理解了、写进了设计文档订正节和 CLAUDE.md。

**然后我在实现方向二时，把目标设成了参照组的实际位姿。**

手臂会落后目标 5cm → 它停在"参照位姿再往后 5cm"处。而**什么都不做**的对照组追的是和参照组
同一个目标、以同样方式落后，**自然就落在参照组实际到过的位置附近**。

实测证实了这个推理：到参照组接触位姿的距离，对照 **0.69cm**，我的"修正"**1.59cm**——
**我把一个本来已经对的东西改坏了，2.3 倍。**

⚠️ **元层面的教训**：我把一个诊断（"目标≠实际"）写进了文档，却没有在**下一步的实现里**
应用它。**知道一条原则和在设计里用上它，是两件事。** 下次做任何"把 A 对齐到 B"的干预，
先问：A 和 B 是同一类量吗？（目标 vs 实际、命令 vs 到达、世界系 vs 局部系——这一轮三种都踩了。）

## 二十七、但拿到了一条比之前强得多的旁证

之前判断"载体不是接触时的手臂位置"，靠的是**间接推断**：结尾驻留让手臂收敛到目标（p05
2.50→0.46cm）而成功率不动。

现在是**直接测量**：对照组在第一次接触时距参照组只有 **0.69cm**，而成功率从 32.3% 掉到
15.7%。方块 4.68cm、夹爪每边余量 1.66cm——**0.69cm 只吃掉四成余量，成功率却腰斩。**

所以"接触位姿几乎一致但成功率腰斩"现在有了直接证据。用户的物理论证（位姿一样就不该失败）
**严格说仍未证伪**（0.69cm ≠ 0），但要用它解释 16.6pp，需要说明这 0.69cm 如何在 1.66cm
余量下造成如此大的影响——这个解释目前不存在。

## 二十八、下一步的分叉（新 session 可直接接）

1. **把方向二做成正确形式**：补"两次运行滞后量之差"这个逐步反馈量，而不是把目标设成对方的
   实际位姿。实现比这次复杂（要逐步参照轨迹），估 1~2 小时。**我的预期是接触残差能压到接近 0
   而成功率仍不显著改善**——如果成立，就正面回答了用户的物理质疑。
2. **换个方向找载体**：三个候选（关节构型、接触时手臂位置、方块在夹爪里的偏心）已全部排除。
   尚未查过的：接触时刻的**速度**（手臂/方块）、接近的**方向**（从哪一侧压下去）、
   自由段是否**碰到过**别的方块。
3. **接受"便宜修不掉"并收尾**：十二组实验已把工程修法排除得比较干净，唯一有效杠杆仍是幅度。
   若要收尾，产出是"失效边界的形状"+ 方法学结论，不是修法。

# 第五轮推理（2026-09-02/03）：接触帧驻留——载体找到了，之前三条"排除"全部撤回

## 二十九、这一轮的起点

用户重申物理论证：sin² 两端斜率为零、指令末端不受影响，再抄平行 MimicGen 的接触位姿把状态
也对齐，arc 成功率理论上该 ≈ MimicGen。要求先把方向二做出来再讨论我的假设。

## 三十、动手前先查上一次为什么错——发现第二个、更大的原因

上一次 `snap_to_reference` 的修正量是 `参照接触位置 − 本 subtask 最后一帧目标`。查代码和数据：
终止信号 `grasp_1`/`grasp_2` 在夹爪动作**同一帧**触发，subtask 在信号后 1 帧结束，再加
`subtask_term_offset_range=(10,20)`。源演示的手臂在接触后 10/15/20 帧走 **10/15/17cm**。
所以上次那个向量里混进了 10~17cm 的"接触后提升"分量。2.13 节归因于滞后，是错的（至多次要）。

**推理陷阱 11：干预对准的是"事件"还是"边界"，先量两者差几帧。** 三次驻留实验（第三、第五修法、
方向二第一版）没有一次落在夹爪动作那一帧上。

## 三十一、五组实验（Group E），核心数字

不抄平行组、只在每次夹爪指令前插 20 帧无噪声驻留（停在序列里已有的名义目标上）：
arc 3.0cm 从 15.7% → **39.0%**，超过 0.5cm 参照的 32.3%；参照自己加驻留 → **50.3%**。
抄平行组实际位姿再驻留：19.7%——这次抄成功了（到参照距离 0.69 → 0.36cm），所以是公平测试，
而它比"停在目标"差 19pp。

## 三十二、信念怎么变的

1. **"接触时手臂位置不是载体"撤回。** 它靠两条证据：第五修法（驻留在 subtask 末尾 = 夹爪动完
   11~23 帧后，收敛的是提升途中的位置）和 0.69cm（成功样本的中位数，失败样本在 1.88cm）。
   两条都不构成排除。载体就是接触帧的水平位置。
2. **"5cm 落后是重放机制的一部分、追上目标就是推离源演示"撤回一半。** 源演示逐帧量：普通帧
   目标−实际中位 4.86cm（91% 大于 0.3cm），夹爪动作帧中位 **0.00cm**（70% 小于 0.3cm）。
   人在要夹要放的那一刻松开摇杆、等臂停稳、再动夹爪。那一帧目标 = 实际，停在目标 = 停在人当时
   的位置。之前把全帧中位数当成每一帧的性质——**推理陷阱 12：一个量的全局中位数不是它在关键
   帧上的值，关键帧要单独量。**
3. **"抄 MimicGen 至少能持平"不成立。** 平行组闭合时离方块 1.12cm、人 0.56cm、它自己只成功
   32%；同场景配对显示抄参照只在参照本来就成功的场景有用（27.5 → 47.9），参照失败的场景抄了
   也白抄（3.5 → 6.2）；停在目标两类场景都救（63.8 / 17.4）。
4. **MimicGen 自己 62% 的失败大头是同一个机制。** 目标序列在源演示的帧号停住，生成的手臂落后
   更多（噪声 + 构型），夹爪指令下达时它还在以 1.7cm/5 帧赶路（人是 1.14，驻留后 0.64）。
   官方有 `num_fixed_steps` 这个驻留参数，放在 subtask **开头**、配置为 0——想到了、放错了地方。
   **patch 候选。**

## 三十三、用户第一次听到结果时的三个反问，以及答案（值得留着，下次还会被问）

- "不是推导出目标点驻留不合适吗？"——那条推导对运动过程成立，对接触帧不成立（第 2 条）。
- "找源演示实际位姿要改代码，不如抄 mimic"——不用找：接触帧上源演示目标 = 实际，变换后就是
  序列里现成的那个点，`hold_pos = poses[c]` 一句话；抄 mimic 才要平行组 + 查表 + 容差。
- "源数据不存人手位置，怎么推出人先停了？"——存的是 `actions`（每步指令位移）和 `eef_pos`；
  重放的 `target_eef_pose` 核对等于 `eef_pos + action[:3]`（误差 0.0000cm）。"人停了"就是
  指令归零，直接记录，不是推断。

## 三十四、还悬着的

- 驻留后 arc 仍差 11.3pp，几乎全在"方块2 放到方块1 上"（61.3 对 69.7）；释放帧方块偏移
  p90 5.34 对 1.70、中位已对齐——手臂到位了，方块在夹爪里歪了。抓取方式（沿 arc 路径接近）
  是下一个要量的。
- 一个生成种子、n=300、驻留 20 帧没调、episode 长 35%，训练侧影响未测。
- 用户定的下一步方向：把"停在源演示实际位姿"和"抓取阶段目标点驻留"结合，追求高产出率。
  注意在接触帧上这两者是同一个点，可探索的是驻留参数（长度、按收敛门控、哪些事件）和多种子。

## 三十五、第二、三批（2026-09-03）：三个悬着的问题的答案

- **换场景成不成立**：成立（50.3 → 55.3，39.0 → 40.3）。
- **剩下的 11pp 在哪**：接近段。把 arc 冻结尾巴从 30% 加到 50%，3.0cm + 驻留 49.7%，跟不加 arc
  持平，释放帧尾巴（p90 5.34 → 1.73cm）消失。门控单独不消这条尾巴。**代价要写清楚**：同一峰值下
  路径积分扰动少约三成——这不是白拿的，是"扰动量 vs 产出率"曲线上换了个点。
- **驻留该不该做成机制**：该。按收敛门控（0.3cm / ≤40 帧）比固定 20 帧再高 5pp、平均帧数相当。
  但五分之一的驻留到上限没收敛——阈值对释放事件可能太紧（目标被下方方块顶住），下一步扫阈值
  或按事件分阈值。
- **生产工作点**：1.2cm + 驻留 50.0%，对比 v1 生产 34.1%。

**当前最合适的组合**：arc（≤3.0cm 冻结 50%，或 1.2cm 冻结 30%）+ 夹爪动作前门控驻留。
**没测的**：门控 + 冻结 50% 同用、门控在 1.2cm、阈值扫描、门控换场景、训练侧影响。

## 三十六、加大幅度（2026-09-04）：鼓包是太快，不是太大

用户想把幅度推到 10cm。离线几何说可行（峰值处离桌 16~21cm），实测产出 51.5 → 6.0%。关键是量了
**实际**弧线：手臂只走出指令的 42~51%，比例几乎不随幅度变——这是一阶低通的特征（控制链时间常数
约 10 帧：`scale=0.5` × PD 在 50ms 内的实现率），不是限位或速度限位（数据里都不贴边）。成功率掉在
搬运段：方块在指间被横向加速度甩偏（释放时偏心 0.86 → 2.84cm），发生在驻留之前，时间救不回。

**推理陷阱 13：把指令幅度当实际幅度**（同一类错误第三次出现：1.2cm 峰值当平均、目标当实际、指令当
实际）。任何"给控制器一个指令"的实验，先量控制器实际做到了多少。

**解法在原因里**：拉长鼓包的时间（重采样自由段）而不是加大幅度；门控保护下重试更高增益；搬运段
小幅度。三条都没跑。

## 三十七、拉长时间（2026-09-04）：追上了反而回不来

拉长 2× 让手臂多追上鼓包（0.38 → 0.59，一阶模型预测得准），但 5cm 产出 26.0 → 22.3%、10cm 6.0 → 4.3%：
进冻结段时离标称路径更远，18 帧尾巴 + 门控拉不回来，方块偏心更大。0cm 拉长 52.7% 说明"慢"本身无害。
**推翻的是我自己上一节的"鼓包太快不是太大"**——精确版本：鼓包的**返回**受冻结段长度限制，鼓包越被
跟上返回越难；而搬运段的方块在这一路上被甩歪，这两条都不是时间能解决的。竖直方向的鼓包最难跟
（0.25 对 0.45），奇异性不是原因。
下一步的分叉：只在接近段（夹爪空的 subtask 0、2）加大幅度——损失集中在搬运段，训练想要的"接近路径
不同"也只需要接近段。等用户定。

## 三十八、用户纠正（2026-09-04）：搬运段不滑，偏心生在闭合那一刻

我推出"搬运段扰动超过噪声就滑、所以只扰抓取段"——两处都错。用户的物理论证（滑动条件是加速度
超过摩擦力）正确，数据坐实：搬运段加速度各幅度完全一样（arc 被滤平，加速度由噪声决定，是源演示
的两倍）；搬运中滑动中位 0.2~0.4cm 不随幅度变；**闭合时的偏心** 0.61 → 2.49cm 随幅度单调增长——
损失生在抓取段的接近段。"只扰抓取段"方向反了，且打翻"全轨迹扰动"的前提，撤回。

**推理陷阱 14：把相关当机制**（偏心 vs 位移的相关被我说成"位移大就滑"）；**陷阱 15：因为难就砍
前提**——创新在难的角落，搬运段不是该抛弃的部分，它反而是承受得住的部分。

术语统一：抓取段（subtask 0/2）、搬运段（1/3）、冻结段（每段末端冻结目标再靠近）、接近段（每段里
靠近交互物体的部分）。

下一版机制（待用户定）：arc 保留在全轨迹；两个旋钮——峰值提前（v3 `PERTURB_ARC_PEAK_FRAC`）拉长返回、
冻结段长度随幅度走；验收指标 = 闭合时偏心回到 0cm 组的 0.61cm 附近。

## 三十九、原则验证（2026-09-04 深夜）：返回提前结束，产出回来了

按定案只动返回时机：峰值 0.5 → 0.25。5cm：闭合偏心 0.85 → 0.69cm，产出 26.0 → 48.0%（加冻结 50%：51.0%）；
10cm + 冻结 50%：偏心 1.85 → 0.68cm，产出 6.0 → **46.7%**，实际弧线中位 2.62、p90 6.0cm 保留。
搬运段滑动和加速度全程不变。用户的原则（全轨迹扰动、不追扰动目标、冻结段前收敛、末端冻结再靠近）
在 5cm 和 10cm 上同时成立。

**这一轮的方法学教训**：两天里我三次提出砍东西（砍幅度、砍搬运段、砍前提），用户三次坚持"在难的
角落找解"，最后解在一个从没用过的现成参数里（v3 峰值位置）。**陷阱 16：先想删什么，后想调什么——
顺序反了。**
